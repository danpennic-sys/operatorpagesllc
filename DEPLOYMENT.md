## Local Development

### Quick Start
```bash
# Clone repository
cd /workspaces/operatorpagesllc

# Copy environment file
cp .env.example .env

# Add your OpenAI API key to .env
# OPENAI_API_KEY=sk-...

# Start services with Docker Compose
docker-compose up --build

# Access application
# Frontend: http://localhost:8080
# Go API: http://localhost:3000
# Python Service: http://localhost:5000
```

### Individual Service Development

#### Go API
```bash
cd services/go-api
go mod download
go run main.go
```

#### Python Service
```bash
cd services/python-chatgpt
pip install -r requirements.txt
python app.py
```

#### Node Frontend
```bash
cd services/node-frontend
npm install
npm start
```

## Railway Deployment

### Prerequisites
1. **Railway Account**: Create at https://railway.app
2. **Railway CLI**: Install with `npm install -g @railway/cli`
3. **OpenAI API Key**: Have your API key ready

### Step 1: Install Railway CLI
```bash
npm install -g @railway/cli
```

### Step 2: Login to Railway
```bash
railway login
```
This opens a browser to authenticate with Railway.

### Step 3: Create a New Project
```bash
railway init
```

### Step 4: Link to Your Repository
```bash
railway link
```

### Step 5: Set Environment Variables
```bash
# Open Railway dashboard to add variables, or use:
railway variables

# Add your variables:
# OPENAI_API_KEY=your_key_here
# GO_PORT=3000
# PYTHON_PORT=5000
# NODE_PORT=8080
```

### Step 6: Deploy
```bash
railway up
```

### Step 7: View Deployment
```bash
railway open
```

This opens your deployment in the Railway dashboard.

### Access Your Deployed Application
```bash
railway logs
```

Your services will be available at Railway-generated URLs.

## Railway Configuration

### File: `railway.yml`

The `railway.yml` file defines your deployment configuration:

```yaml
services:
  go-api:
    build: ./services/go-api
    port: 3000
    environment:
      - GO_PORT=3000
      - PYTHON_SERVICE_URL=${PYTHON_SERVICE_URL}
      - NODE_SERVICE_URL=${NODE_SERVICE_URL}
    depends_on:
      - python-chatgpt

  python-chatgpt:
    build: ./services/python-chatgpt
    port: 5000
    environment:
      - PYTHON_PORT=5000
      - OPENAI_API_KEY=${OPENAI_API_KEY}

  node-frontend:
    build: ./services/node-frontend
    port: 8080
    environment:
      - NODE_PORT=8080
      - GO_API_URL=${GO_API_URL}
      - PYTHON_SERVICE_URL=${PYTHON_SERVICE_URL}
    depends_on:
      - go-api
      - python-chatgpt
```

## Environment Configuration

### Local Development (.env)
```env
OPENAI_API_KEY=sk-...
GO_API_URL=http://localhost:3000
PYTHON_SERVICE_URL=http://localhost:5000
NODE_SERVICE_URL=http://localhost:8080
GO_PORT=3000
PYTHON_PORT=5000
NODE_PORT=8080
NODE_ENV=development
PYTHON_ENV=development
GO_ENV=development
```

### Production (Railway)
Set these variables in the Railway dashboard:
- `OPENAI_API_KEY` - Your OpenAI API key
- `GO_PORT` - Port for Go service (usually 3000)
- `PYTHON_PORT` - Port for Python service (usually 5000)
- `NODE_PORT` - Port for Node service (usually 8080)
- `NODE_ENV` - Set to `production`
- `PYTHON_ENV` - Set to `production`
- `GO_ENV` - Set to `production`

### Service URLs (Auto-generated by Railway)
- `GO_API_URL` - Set automatically by Railway
- `PYTHON_SERVICE_URL` - Set automatically by Railway
- `NODE_SERVICE_URL` - Set automatically by Railway

## Continuous Integration/Deployment

### GitHub Actions Setup

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy to Railway

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Install Railway CLI
        run: npm install -g @railway/cli
      
      - name: Deploy
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}
        run: railway up
```

1. Get your Railway token: `railway token`
2. Add to GitHub secrets as `RAILWAY_TOKEN`
3. Push to trigger deployment

## Security

### Production Best Practices

1. **Never commit secrets**
   ```bash
   # .gitignore should include:
   .env
   .env.local
   ```

2. **Use Railway secrets**
   - Store all sensitive data in Railway variables
   - Never hardcode API keys

3. **Enable HTTPS**
   - Railway provides HTTPS by default
   - Use custom domains with SSL

4. **API Authentication**
   - Consider adding JWT or API keys
   - Implement rate limiting
   - Use API gateway

5. **CORS Configuration**
   - Limit allowed origins
   - Use environment-specific settings

6. **Database Security**
   - Use strong passwords
   - Enable encryption at rest
   - Regular backups
   - Restrict network access

## Troubleshooting

### Services Won't Start
```bash
# Check logs
docker-compose logs

# Rebuild images
docker-compose down -v
docker-compose up --build

# Clear cache
docker system prune -a
```

### OpenAI API Errors
- Verify API key is valid
- Check API key has permissions
- Ensure account has credits
- Check rate limits

### Port Conflicts
```bash
# Find what's using the port
lsof -i :3000
lsof -i :5000
lsof -i :8080

# Kill process if needed
kill -9 <PID>
```

### Service Communication Issues
```bash
# Check network connectivity
docker network ls
docker network inspect operatorpagesllc_operatorpages-network

# Test inter-service communication
docker exec go-api curl http://python-chatgpt:5000/health
```

### Railway Deployment Issues
```bash
# Check Railway status
railway status

# View deployment logs
railway logs

# Restart deployment
railway redeploy

# Check environment variables
railway variables
```
